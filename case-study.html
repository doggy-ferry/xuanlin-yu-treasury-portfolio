Foreign-currency payment control and actual/forecast cash-flow automation

Provenance. Built independently with synthetic data to demonstrate transferable cash-flow modelling, control and automation capabilities developed through professional treasury experience. The author defined the business rules, data design and acceptance tests; AI-assisted coding supported implementation and documentation.

1. Foreign-currency pre-payment control

The main value is moving an irreversible payment risk to before the payment. Each payment is laid out on one row so a reviewer can see the facts, the matches, the reason for any exception and the next action.

Vendor Reference Bridge

If a long account number is truncated, reformatted or converted to a number by Excel, joining AP and invoices on the account can fail. The bridge first obtains a generic supplier reference key from the account, currency and payment-date combination that can still be identified, and then totals the invoice amounts on that key. It is an explainable, reviewable alternative join path, not a way of skipping a control.

2. Actual/forecast cash-flow automation

Reading the sources and maintaining the target workbook are kept separate. Power Query obtains, merges and shapes the sources. VBA handles the Excel objects: locating headers, pasting values, extending formulas, writing timestamps and refreshing pivots. Before the cutoff date the report takes actuals; after it, forecast.

  1. A Setting sheet holds the generic root path, target workbook and sheet keys, key headers, company code and date/time cells.
  2. Query_AP, Query_BANK and Query_AR read the latest or combined files and keep account identifiers as text.
  3. The macro refreshes the queries and stops if a workbook, sheet, query table or required setting is missing, or if a query returns no data.
  4. It locates the target area by header, clears old values and pastes values only, keeping the target formatting.
  5. It extends adjacent formula columns to the last row of the new data; it writes timestamps and refreshes pivots where coded.
  6. The CashFlow sheet switches between actual and forecast at the cutoff and shows a control difference between the components and the total.

Design decisions and known limits

  • The AP header comparison intentionally runs to nSrc - 1, because Power Query appends a final Source File column for traceability; this is commented in the code.
  • CLEAR_LEFTOVER defaults to False. If the current month has fewer rows than the prior month, residual formula rows below the current range may remain in a pivot-table source. Change it only after testing the target workbook's formula and pivot boundaries.
  • Source layout or header changes need maintenance and re-acceptance. Excel suits the current scale; multi-user, permission and logging needs would call for a database or service.
  • Automation boundary: the controls identify contradictions covered by the defined rules. They cannot prove that source data is true, complete or untampered.
