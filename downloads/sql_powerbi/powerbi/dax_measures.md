## 1. Total Actual

- **Purpose:** Net Actual cash movement in JPY (inflows minus outflows).
- **Logic:** SUM(amount_base) of fact_cashflow rows whose scenario is Actual.
- **Filter context:** follows Date, Entity, Currency and Category slicers; JPY, so currencies can be added.
- **Format:** `#,0`

```dax
Total Actual =
CALCULATE ( SUM ( fact_cashflow[amount_base] ), fact_cashflow[scenario] = "Actual" )
```

## 2. Total Forecast

- **Purpose:** Net Forecast cash movement in JPY, valued at the planning rate.
- **Logic:** SUM(amount_base) of fact_cashflow rows whose scenario is Forecast.
- **Filter context:** same as Total Actual.
- **Format:** `#,0`

```dax
Total Forecast =
CALCULATE ( SUM ( fact_cashflow[amount_base] ), fact_cashflow[scenario] = "Forecast" )
```

## 3. Forecast Variance

- **Purpose:** How far Actual ended from Forecast. Negative = less cash than planned.
- **Logic:** Total Actual - Total Forecast.
- **Filter context:** same as Total Actual; both parts see the same filters.
- **Format:** `#,0`

```dax
Forecast Variance =
[Total Actual] - [Total Forecast]
```

## 4. Forecast Variance %

- **Purpose:** Variance relative to the size of the forecast.
- **Logic:** DIVIDE(Forecast Variance, ABS(Total Forecast)); BLANK when the forecast is zero, so there is never a divide-by-zero error.
- **Filter context:** same as Total Actual.
- **Format:** `0.0%`

```dax
Forecast Variance % =
DIVIDE ( [Forecast Variance], ABS ( [Total Forecast] ) )
```

## 5. Cash Inflow

- **Purpose:** Actual cash received in JPY (positive rows only).
- **Logic:** SUM(amount_base) for Actual rows where amount_base > 0.
- **Filter context:** same as Total Actual. Pooling and borrowing receipts count as inflow.
- **Format:** `#,0`

```dax
Cash Inflow =
CALCULATE ( SUM ( fact_cashflow[amount_base] ), fact_cashflow[scenario] = "Actual", fact_cashflow[amount_base] > 0 )
```

## 6. Cash Outflow

- **Purpose:** Actual cash paid in JPY (negative rows only); shown as a negative number.
- **Logic:** SUM(amount_base) for Actual rows where amount_base < 0.
- **Filter context:** same as Total Actual.
- **Format:** `#,0`

```dax
Cash Outflow =
CALCULATE ( SUM ( fact_cashflow[amount_base] ), fact_cashflow[scenario] = "Actual", fact_cashflow[amount_base] < 0 )
```

## 7. Net Cash Flow

- **Purpose:** Net Actual movement taken from the daily cash-position table (reconciles to Total Actual).
- **Logic:** SUM(net_cash_flow_base) of fact_cash_position.
- **Filter context:** follows Date and Entity only (the position table is in JPY and has no currency or category).
- **Format:** `#,0`

```dax
Net Cash Flow =
SUM ( fact_cash_position[net_cash_flow_base] )
```

## 8. Closing Cash Position

- **Purpose:** Cash balance at the end of the period in view, all selected entities added up (JPY).
- **Logic:** closing_balance_base on the LAST date in the current filter context (last day of a month on a month axis, last day of the data on a card).
- **Filter context:** follows Date and Entity. A balance is not additive over time, so only the last day is used.
- **Format:** `#,0`

```dax
Closing Cash Position =
VAR LastDay = MAX ( fact_cash_position[full_date] )     -- not "LastDate": that is a DAX function name and the engine rejects it
RETURN
    CALCULATE ( SUM ( fact_cash_position[closing_balance_base] ), fact_cash_position[full_date] = LastDay )
```

## 9. Payment Count

- **Purpose:** Number of payment instructions in the control run.
- **Logic:** DISTINCTCOUNT(payment_id) of fact_payment_control.
- **Filter context:** follows Date, Entity, Currency, Vendor and Exception slicers.
- **Format:** `#,0`

```dax
Payment Count =
DISTINCTCOUNT ( fact_payment_control[payment_id] )
```

## 10. Total Payment Amount Base

- **Purpose:** Value of the payment instructions in JPY at the planning rate.
- **Logic:** SUM(payment_amount_base).
- **Filter context:** same as Payment Count. Original-currency amounts (payment_amount) are shown only next to the currency code and are never summed across currencies.
- **Format:** `#,0`

```dax
Total Payment Amount Base =
SUM ( fact_payment_control[payment_amount_base] )
```

## 11. Exception Count

- **Purpose:** Payments that failed at least one defined check (High or Medium risk).
- **Logic:** Payment Count where risk_level is not Passed.
- **Filter context:** same as Payment Count.
- **Format:** `#,0`

```dax
Exception Count =
CALCULATE ( [Payment Count], fact_payment_control[risk_level] <> "Passed" )
```

## 12. Exception Rate

- **Purpose:** Share of payments that need attention.
- **Logic:** DIVIDE(Exception Count, Payment Count).
- **Filter context:** same as Payment Count.
- **Format:** `0.0%`

```dax
Exception Rate =
DIVIDE ( [Exception Count], [Payment Count] )
```

## 13. High Risk Count

- **Purpose:** Payments to hold until confirmed (red).
- **Logic:** Payment Count where risk_level = High.
- **Filter context:** same as Payment Count.
- **Format:** `#,0`

```dax
High Risk Count =
CALCULATE ( [Payment Count], fact_payment_control[risk_level] = "High" )
```

## 14. Passed Payment Count

- **Purpose:** Payments that passed every defined check (green). Passing the defined checks is not a guarantee that a payment is correct.
- **Logic:** Payment Count where risk_level = Passed.
- **Filter context:** same as Payment Count.
- **Format:** `#,0`

```dax
Passed Payment Count =
CALCULATE ( [Payment Count], fact_payment_control[risk_level] = "Passed" )
```

## 15. Unmatched Vendor Count

- **Purpose:** Payments that could not be tied to a vendor in the vendor master. They stay in the report instead of being dropped.
- **Logic:** Payment Count where vendor_matched_flag = 0.
- **Filter context:** same as Payment Count.
- **Format:** `#,0`

```dax
Unmatched Vendor Count =
CALCULATE ( [Payment Count], fact_payment_control[vendor_matched_flag] = 0 )
```
